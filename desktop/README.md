# Chesster — настольная версия

Та же игра, что и в браузере (`../index.html`), но в виде полноценного приложения
для компьютера: своё окно, меню, иконка, системные диалоги и — главное — возможность
запускать внешние шахматные движки (Rodent IV / V) **отдельным нативным процессом**,
который использует оперативную память и ресурсы устройства напрямую, без лимитов
вкладок браузера.

## Быстрый старт (без сборки установщика)

```bash
cd desktop
npm install        # поставит electron и electron-builder
npm start          # открывает приложение с ../index.html внутри
```

## Сборка установщика (exe, Windows)

Целевая платформа — **Windows**; конфигурации mac/linux из сборки убраны.

```bash
npm run dist        # Windows: NSIS-установщик + portable exe  → desktop/dist/
```

Или одной командой из корня проекта: **`push-release.bat`** — коммит, пуш и тег `v<версия>`,
после чего установщик собирает и публикует GitHub Actions (`.github/workflows/release.yml`).

Готовые файлы появляются в `desktop/dist/`. Для Windows это
`Chess Setup x.x.x.exe` (установщик) и `Chess x.x.x.exe` (portable, работает
без установки с флешки). Настройки `electron-builder` — в `package.json` (блок `build`).

Иконки пересоздаются командой `npm run icons` (нужен Pillow; векторный рендер —
через resvg-py, при его отсутствии включается запасной рисовальщик).

С 3.3 установщик несёт **предустановленный Rodent V**: в CI шаг «Скачать Rodent V (GPL)»
забирает релиз движка с GitHub, распаковывает exe и папки `personalities/`, `nets/`,
`books/`, кладёт рядом лицензию и `NOTICE.txt` — `extraResources` упаковывает это в
`resources/engine/`. Для локальной сборки `npm run dist` запускает predist
(`tools/ensure-engine-dir.js`): пустая папка `engine/rodent` тоже годится — приложение
полностью работоспособно без предустановленного движка. Папка `engine/` в git не попадает.

## Известные дефекты прошлых сборок и их защита

* **1.0.0: пустое окно с фоном и меню.** Упакованный `main.js` искал `index.html` через
  `__dirname/..`, что внутри `app.asar` указывает мимо `resources/app/`, куда кладёт веб-часть
  `electron-builder`. Окно открывало страницу ошибки: работали только роли меню («Выход»,
  «Полный экран»). Теперь `findIndexPath()` перебирает упаковку, разработку и portable-раскладку,
  а при промахе показывает диагностическое окно со списком проверенных путей; добавлен обработчик
  `did-fail-load`. Раскладки проверены тестом `uitest8.js` прямо на функции из `main.js`.
* **1.0.0: маленькое «техническое» окно.** Теперь окно стартует развёрнутым (`win.maximize()`),
  минимальный размер поднят до 900×620, а интерфейс в обёртке крупнее браузерного
  (класс `body.desktop`): панель 520 px открыта по умолчанию, крупнее иконки, статус и шрифты.
* **2.0: нативная панель меню и неполный экран.** Полоса «Партия/Вид/Инструменты/Справка»
  оставалась видимой даже в полном экране, а окно стартовало развёрнутым, но с рамкой.
  В 2.1 нативное меню отключено (`Menu.setApplicationMenu(null)`), действия переехали в меню
  приложения «⋮» в шапке (с 2.4 — окно настроек «⚙»); старт — в настоящем полном экране
  (настройка «Запускать во весь экран», переключение F11 или «⚙ Настройки → Вид → Полный экран»).
* **2.0: перевес материала считался по взятиям.** Съеденный превращённый ферзь давал «+9»
  съевшей стороне, а само превращение материал не добавляло. В 2.1 перевес считается по
  фактической расстановке на доске, превращение сразу прибавляет материал проводящей стороне.
* **2.0: прокрутка под доской.** Блок статуса убран из-под доски во вкладку «Ходы» (при мате,
  пате или ничьей меню само открывается на ней, если было закрыто), в шапке появился чип
  состояния; под доской — только ряды взятых фигур и панель иконок. Страничная прокрутка
  в приложении отключена, боковой ползунок не появляется.

## Что добавляет обёртка сверх браузерной версии

| Возможность | Как работает |
|---|---|
| Нативное окно, иконка, заголовок | `main.js`: BrowserWindow. Нативная панель меню отключена с 2.1 (`Menu.setApplicationMenu(null)`) — частые действия переехали во внутристраничное меню (с 2.4 — окно настроек «⚙») |
| Системный диалог сохранения файлов | IPC `dialog:saveFile` — выгрузка архива PGN пишет файл куда скажет пользователь |
| Ссылки (Lichess) в системном браузере | IPC `shell:openExternal`, внутри окна внешние переходы запрещены |
| **Внешний движок отдельным процессом** | IPC `engine:spawn`: `child_process.spawn(exe)`, строки UCI ходят через stdin/stdout и IPC; движок — обычный процесс со своей оперативной памятью,хэш-таблицей и потоками |
| Память устройства | Данные приложения лежат в `userData` Electron (не в профиле браузера), архив партий — файлом `archive.json` без лимита; движок и его кэш живут в своей ОС-памяти; большие файлы пишутся на диск системными диалогами |
| **Выход из приложения** | IPC `app:quit` (кнопка «⏻ Выход» внизу окна настроек, 3.1): главный процесс гасит процесс движка, закрывает окно и вызывает `app.quit()`. В полноэкранном запуске у окна нет ни заголовка, ни крестика, поэтому без этой кнопки выйти было нечем |
| Безопасность | `contextIsolation: true`, `nodeIntegration: false`, `sandbox: true`; страница видит только мост `window.Chesster` из `preload.js` |

Частые действия (новая партия, вернуть ход, перевернуть, стереть стрелки, копировать
FEN/PGN, открыть в Lichess, сохранение/выгрузка архива, справка) живут во
внутристраничном меню; страница подписывается на события меню обёртки через
`Platform.onMenu(...)`, но с 2.1 их некому отправлять — нативная панель отключена
(в `main.js` на macOS остаётся лишь минимальное роль-меню Quit/Hide/Minimize).

## Rodent IV / Rodent V: два пути подключения

Родные сборки Rodent — исполняемые файлы Windows/Linux под GPL, поэтому в репозиторий
они не вкладываются. С версии 3.2 проверено живое рукопожатие **Rodent V 1.2** (2026, Go + NNUE,
~3400 CCRL Elo): формат строк UCI тот же, что у Rodent IV, разбор протокола общий, а приложение
дополнительно читает `id name` / `id author` и показывает, как движок представился.
С установщика 3.3 **Rodent V 1.2 предустановлен**: движок вложен в ресурсы приложения
(GPL, как отдельная программа; текст лицензии — рядом с exe), а в «⚙ → Движок» появляется
кнопка «🖥 Использовать предустановленный» — скачивать ничего не нужно (IPC `engine:bundled`
ищет exe в `resources/engine/`). Ручные маршруты ниже по-прежнему работают: portable-сборка,
своя копия движка, Rodent IV.

Приложение предоставляет оба маршрута:

1. **Десктоп (рекомендуется, полная сила).** Настройки «⚙» → «Движок» → «🖥 Выбрать exe…» →
   указать исполняемый файл Rodent V или IV. Обёртка запускает его отдельным процессом
   (`child_process.spawn` с рабочей папкой движка, чтобы он нашёл свои `personalities/`,
   `nets/` и `books/` — у Rodent V пути внутри «личностей» относительные), выполняет
   рукопожатие `uci` / `isready`, передаёт `position fen …` и `go …`, принимает
   `info`/`bestmove`. Сила — пресетами под уровни «Лёгкий / Средний / Сильный»
   (`MoveTime`, `DepthLimit`, `NodeLimit` идут в команду `go` — их понимает и Rodent V),
   стиль — опциями самого движка (у Rodent V это `PersonalityFile`, а точная сила —
   `UCI_LimitStrength` + `UCI_Elo` 800…3000). Приложение запускает exe без аргументов —
   это обычный режим Rodent V; режимы `alloptions`/`nooptions` задаются аргументом командной
   строки и пока не передаются.

   С версии 3.1 подключённый exe **считается установленным движком**: кнопки «Использовать»,
   «Проверить» и «Удалить» работают, карточка показывает имя файла и путь, а путь
   запоминается в настройках — при следующем запуске приложения процесс поднимается сам
   (`restoreNativeEngine()`). Если файл перемещён или не запустился, приложение пишет причину
   в журнал и возвращается к встроенному боту, а не играет «молча ослабленным».
2. **Браузер (WASM).** Та же категория настроек, поле выбора файла: принимается ОДИН файл
   сборки Rodent, скомпилированной в WebAssembly/asm.js (архивы `.zip`/`.7z` отклоняются
   с подсказкой — страницу нельзя попросить «распаковать»; у Rodent V официальной веб-сборки
   нет, движок написан на Go). Файл сохраняется в IndexedDB
   (бюджет архива партий в localStorage не трогает) и запускается в Web Worker
   через обвязку `rodent4-worker.js`. С версии 3.1 **обвязка вшита в `index.html`**
   сборщиком (`build.js`, токен `/*@ENGINEWORKER@*/`), поэтому приложение остаётся одним
   файлом и запускает движок без интернета. Контракт обвязки (какие функции модуль
   экспортирует и импортирует) описан в шапке этого файла.

**Опции движка не выдуманы, а прочитаны.** В ответ на `uci` движок перечисляет свои опции
строками `option name … type …`; приложение разбирает их (`Engines.parseUciOption`) и строит
форму по настоящему списку: `spin` — число с пределами, `check` — галочка, `combo` — список
значений (так выбирается «личность» Rodent IV), `string` — текст (так Rodent V получает
`PersonalityFile`), `button` — кнопка без значения (так работает `Clear Hash`).
До рукопожатия показывается запасной список из каталога. Все строки обмена видны в
«Журнале UCI» в карточке движка.

Пока ни один внешний движок не подключён, компьютер считает встроенным ботом —
приложение полностью работоспособно без каких-либо дополнительных файлов.

Где взять сам движок: **Rodent V** — архив релиза `release-1-2.zip`
(<https://github.com/nescitus/Rodent-V/releases>, внутри exe для Windows, бинарник для Linux,
подпапки `personalities/`, `nets/`, `books/` и `MANUAL.md`; распакуйте целиком в одну папку
и укажите `rodent_v_1.2.exe`); **Rodent IV** — финальный пакет автора `FinalRodent.7z`
(<http://www.pkoziol.cal24.pl/rodent/download.htm>) или репозиторий
<https://github.com/nescitus/rodent-iv> (каталог `exe/`, для macOS — `mac/`). Лицензия — GPL,
в репозиторий приложения движок не вкладывается: пользователь добавляет свою копию,
она остаётся на его устройстве и никуда не отправляется.

## Обновления

Версия приложения одна на все среды — `../version.json` (сейчас 3.3); она попадает в категорию
«О программе» окна настроек и в имя кэша PWA.

* Десктоп: автообновление через **electron-updater** с GitHub-релизов `naemnik6/Chess`.
  Чтобы оно работало, важны три вещи:
  1. `electron-updater` указан в **`dependencies`** `package.json` (не в `devDependencies` —
     electron-builder пакует только production-зависимости; раньше из-за этого приложение
     писало «Автообновление не настроено»);
  2. заполнен блок `build.publish` (`provider: github`, `owner: naemnik6`, `repo: Chess`) —
     из него electron-builder при сборке генерирует `resources/app-update.yml` с адресом
     источника обновлений;
  3. приложение установлено из NSIS-установщика (portable-сборка обновляться не умеет,
     для неё — заменить exe вручную).
  Проверка обновлений выполняется **автоматически в фоне при каждом запуске** (через 4 с
  после открытия окна) и вручную: «⚙ Настройки → О программе → Проверить обновления». Все события
  (`checking-for-update`, `update-available`, `update-not-available`, `download-progress`,
  `update-downloaded`, `error`) логируются: `console.log` главного процесса (видно при
  запуске из терминала) и канал `updater:event` в страницу — строки `[updater]` в DevTools
  (Ctrl+Shift+I). При ошибке интерфейс показывает её текст и диагностику (упаковано ли
  приложение, загружен ли updater, на месте ли `app-update.yml`), а не «не настроено».
  Так как приложение выпускается без цифровой подписи кода, Windows может блокировать
  автоустановку — на этот случай в окне результата и в «О программе» есть кнопка
  «⬇ Скачать обновление вручную»: открывает
  `https://github.com/naemnik6/Chess/releases/latest` в браузере по умолчанию.
  Данные (профили, настройки) лежат в `userData` и переустановку переживают; архив партий
  хранится там же отдельным файлом `archive.json` — без ограничений по размеру (в браузере
  лимит действует, но отключается настройкой «Хранить архив без ограничения размера»).
* PWA/браузер: новая версия применяется сервис-воркером по имени кэша `chesster-<версия>-<дата>`.

## Установка как веб-приложение (PWA)

Без всяких сборщиков игру можно поставить из браузера: рядом с `index.html` лежат
`manifest.webmanifest` и `sw.js`. При открытии по `https://` браузер предложит
«Установить приложение», а сервис-воркер кэширует всё для работы офлайн.
На `file://` и в песочницах регистрация молча пропускается — игра работает как раньше.

## Раскладка папки

```
desktop/
├── main.js            ← главный процесс Electron (окно, IPC, движок-процесс, автообновление)
├── preload.js         ← мост window.Chesster (contextIsolation)
├── smoketest.js       ← смоук-тест автообновлений main.js на моках (node desktop/smoketest.js)
├── package.json       ← зависимости и конфиг electron-builder
├── icon.py            ← генератор иконок из SVG-фигур
├── rodent4-worker.js  ← шаблон JS-обвязки WASM-движка для Web Worker (контракт UCI);
│                          при сборке вшивается в index.html (build.js)
├── README.md          ← этот файл
└── icons/             ← icon.svg, icon-16…512.png, icon.ico
```
