# Tauri: оценка переноса десктоп-обёртки

> Версия документа: 3.0 · папка обёртки: `desktop/tauri/`

## Коротко

Перенос **реален и технически несложен**: 100 % интерфейса приложения — это
один `index.html`, который Tauri умеет отдавать как есть, а вся «нативная»
часть (сохранение файлов, внешние ссылки, запуск UCI-движка процессом) уже
написана на Rust в `desktop/tauri/src/main.rs` и повторяет API электронного
`preload.js` один в один. К версии 3.0 каркас доведён до **собираемого
состояния** (добавлены `Cargo.toml`, `build.rs`, `capabilities/`, мост
`bridge.js`, папка фронтенда `dist/`, исправлены ошибки конфигурации и
блокирующие вызовы в главном потоке), но **сборка не проверена
компиляцией**: в песочнице разработки нет тулчейна Rust и системных
библиотек WebView. Первая проверка — на вашей машине или в GitHub Actions
(черновой workflow `.github/workflows/tauri.yml`, запускается вручную).

## Зачем вообще Tauri

| | Electron (сейчас) | Tauri v2 |
|---|---|---|
| Движок рендеринга | свой Chromium (~200 МБ) | системный WebView (WebView2 / WebKitGTK) |
| Установщик Windows | ~80–100 МБ | ~5–15 МБ |
| Память в покое | ~150–250 МБ | обычно заметно меньше |
| Бэкенд | Node.js | Rust |
| Автообновление | electron-updater (уже работает*) | tauri-plugin-updater (нужна отдельная подпись артефактов) |

\* при публичном репозитории с опубликованными релизами.

## Что уже сделано (3.0)

Каркас в `desktop/tauri/` доведён до состояния, когда сборке ничего не мешает
кроме самого факта компиляции Rust на вашей машине:

- **`Cargo.toml`, `build.rs`** — крейт на tauri 2 + плагин диалогов; раньше
  их не было, сборка была в принципе невозможна. Неиспользуемый
  `tauri-plugin-shell` убран (ссылки открываются напрямую из Rust) — меньше
  зависимостей и быстрее первая компиляция.
- **`capabilities/default.json`** — только события ядра и окно (полный
  экран, заголовок). Разрешение `dialog:default` JS не выдаётся: файловые
  диалоги вызываются из Rust-кода, где разрешения не требуются.
- **`bridge.js`** — мост `window.Chesster`, внедряется до загрузки страницы
  (`initialization_script`), повторяет форму ответов Electron:
  `saveFile`, `openExternal`, `pickEngine`, `spawnEngine`, `engineWrite`,
  `engineKill`, `onEngineLine/Exit/Error`, `setFullscreen`, `isFullscreen`,
  `setTitle`, `onMenu`, `appReady`, `quitApp`. `src/platform.js` определит среду как
  `tauri` без единой строчки хардкода — слой платформ это уже умеет.
- **`src/main.rs`** — Rust-команды: нативное сохранение файла через диалог,
  открытие внешних ссылок, выбор и запуск UCI-движка отдельным процессом
  (под Windows — без консольного окна, `CREATE_NO_WINDOW`), трансляция строк
  движка в WebView событиями `engine:line` и выход из приложения (`quit_app`).
- **`dist/` — отдельная папка фронтенда.** `frontendDist` указывает на
  `desktop/tauri/dist`, а не на корень проекта: иначе в бинарник попал бы
  весь репозиторий вместе с `desktop/node_modules` (сотни мегабайт
  Electron-зависимостей). Папку собирает `build.js` автоматически
  (`index.html` + манифест + иконка). `sw.js` туда намеренно не копируется:
  в обёртке офлайн-кэш не нужен, регистрация сервис-воркера тихо отменяется.
- **`.gitignore`** внутри `desktop/tauri/` — `target/` и `gen/schemas/` не
  попадут в git (важно: `push-release.bat` делает `git add .`).

### Исправленные ошибки прежней версии

- `beforeBuildCommand` указывал на несуществующий `../build.js`. Теперь
  `node ../../build.js || node build.js` — команда работает и из
  `desktop/tauri`, и из корня репозитория (как в GitHub Actions).
- В CSP не было `connect-src ipc: http://ipc.localhost` — без этого
  IPC-вызовы в WebView2 (Windows) блокируются политикой. Инлайновый скрипт
  приложения при этом остаётся разрешён: Tauri сам считает хеши локальных
  скриптов и дописывает их в `script-src` на этапе компиляции.
- `devUrl` требовал dev-сервер на :1420, которого нет — убран, `tauri dev`
  грузит собранный фронтенд напрямую.
- Заголовок окна приведён к Electron-варианту (`Chess`), `productName` — к
  имени установщика (`Шахматы`).

### Что усилено после ревизии кода

- **Все команды помечены `#[tauri::command(async)]`.** Без этого Tauri
  выполняет команду в главном потоке: системный диалог сохранения или выбора
  движка подвесил бы окно, а в худшем случае — взаимно заблокировался
  (диалог ждёт главный поток, команда ждёт диалог). С `(async)` Tauri
  уводит команду в пул потоков.
- **`save_file` принимает текст (`String`), а не `Vec<u8>`.** Вложенный
  `Uint8Array` внутри JSON-аргументов IPC Tauri не переносит (raw-транспорт
  доступен, только когда ArrayBuffer является всем аргументом целиком), а
  приложение сохраняет исключительно текст — PGN и JSON. Мост приводит
  данные к UTF-8 (`toText`).
- **Движок глушится при выходе** (`RunEvent::Exit`) и перед новым запуском —
  как в Electron, чтобы не оставлять висящих процессов Rodent.
- **Рабочая папка процесса движка — папка exe** (`cmd.current_dir(parent)`, 3.2):
  Rodent V ищет `personalities/`, `nets/` и `books/` по относительным путям, поэтому
  без `current_dir` «личности» и книги молча не загружались бы (в Electron `cwd`
  выставлялся изначально).
- **Кнопка «⏻ Выход» работает и здесь** (3.1): команда `quit_app` гасит движок
  и вызывает `app.exit(0)`. В полноэкранном режиме у окна Tauri нет ни заголовка,
  ни крестика, поэтому без этой команды выйти из приложения было нечем.
  Разрешений в `capabilities/` команда не требует — это собственный код Rust.
- **Ссылки открываются через `rundll32 url.dll,FileProtocolHandler`,** а не
  `cmd /C start`: оболочка разбила бы адрес Lichess по символу `&`, а заодно
  исчезает риск инъекции в командную строку. Дополнительно адрес
  проверяется (только http/https, без кавычек и управляющих символов).

## Чего пока нет (осознанно) — план по этапам

**Этап 1 — первая сборка (минуты).** Нужно: Rust (rustup), на Windows —
VS Build Tools + WebView2 (обычно уже есть), на Linux —
`libwebkit2gtk-4.1-dev libappindicator3-dev librsvg2-dev patchelf`.

```bat
cd desktop\tauri
cargo install tauri-cli --version "^2"
cargo tauri build
```

`cargo tauri build` сам запустит `node ../../build.js` (это
`beforeBuildCommand`), так что `index.html` и папка `dist/` будут свежими.
Если собираете «голым» `cargo build` без CLI — сначала выполните
`node build.js` из корня проекта, иначе Tauri не найдёт `dist/`.

Для macOS дополнительно понадобится `icon.icns` (генерируется одной
командой: `cargo tauri icon desktop/icons/icon-512.png`); в репозитории
лежат `.ico` и PNG — их достаточно для Windows и Linux.

Готовые установщики появятся в `desktop/tauri/target/release/bundle/`
(Windows: `.msi` и `.exe` NSIS). Либо запустите в GitHub Actions workflow
**«Tauri (draft build)»** (кнопка Run workflow) — он соберёт Windows- и
Linux-варианты и приложит их артефактами.

**Этап 2 — паритет с Electron.** Три задачи, все упираются в решения,
которые нельзя принять «вслепую» без первой рабочей сборки:

1. *Архив файлом на устройстве.* В Electron `archiveRead/archiveWrite` —
   синхронный `sendSync`; IPC Tauri только асинхронный. Чтобы не рисковать
   данными, мост намеренно НЕ отдаёт эти функции: архив живёт в
   localStorage WebView (сохраняется между запусками, но с браузерной
   квотой). Полноценный перенос = сделать файловый транспорт `store.js`
   асинхронным (одна функция загрузки + очередь записи), после чего
   включить в `bridge.js` заготовленные команды Rust. Работа на полдня,
   но её надо тестировать на живой сборке.
2. *Автообновление.* `tauri-plugin-updater` + генерация ключа подписи
   (`cargo tauri signer generate`), `createUpdaterArtifacts: true`, ключ в
   секреты CI, эндпоинт — те же GitHub-релизы
   (`.../releases/latest/download/latest.json`). Формат артефактов другой
   (не `latest.yml`, а `latest.json` + `.sig`), поэтому релизный конвейер
   получит ещё одну job — после того, как Electron-релизы перестанут быть
   единственными.
3. *Нативное меню и состояние окна.* `MenuBuilder` из tauri 2 (пункты уже
   заведены в мост через `onMenu`) + `tauri-plugin-window-state` (позиция
   и размер окна между запусками). Мелочи, добавляются за один подход.

**Этап 3 — смена основной обёртки.** Когда сборка зелёная, а этап 2 закрыт:
`tauri.yml` получает триггер на теги `v*`, `push-release.bat` и README
переключаются на Tauri-артефакты, Electron остаётся запасным вариантом
(или убирается — по вашему решению).

## Риски

- **Непроверенная компиляция.** Rust-код написан по документации Tauri v2
  (проверены: механизм `(async)`-команд, хеширование инлайновых скриптов в
  CSP, разрешение путей в конфигурации), но не собран — в песочнице
  разработки нет тулчейна Rust и системных библиотек WebView. Первая сборка
  может потребовать мелких правок версий зависимостей.
- **WebView ≠ Chromium.** На Windows это WebView2 (тот же Chromium, рисков
  минимум), на Linux — WebKitGTK (старее; стоит прогнать UI-тесты в
  `tauri.yml` и посмотреть на приложение глазами). На Windows приложение
  визуально не должно отличаться вообще.
- **Подпись обновлений.** Без ключа подписи апдейтер Tauri не работает —
  это разовая настройка, но её нельзя пропустить.

## Вывод

Переносить можно уже сейчас: код приложения менять не нужно вообще (один
`index.html`), мост и Rust-команды написаны, конфигурация исправлена.
Ближайшее действие за вами — запустить `cargo tauri build` (или workflow
«Tauri (draft build)») и прислать результат: если сборка зелёная,
закрываем этап 2 и делаем Tauri основной обёрткой.
